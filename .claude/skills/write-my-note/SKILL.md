# Заметка в ленту

Заметка это одна мысль, записанная сразу, пока она горячая. Между твитом и абзацем статьи. Заголовка нет, вывода нет, вступления нет. Читатель открывает `/notes/` посмотреть, чем автор живёт между статьями.

## 0. Калибровка голоса

Прочитать две-три последние заметки из `/home/ubuntu/pet/my-blog/src/content/notes/` (если папка пустая или там только черновики, взять два коротких эссе из `src/content/blog/ai/`: `nostalgia-for-complexity.md`, `how-not-to-lose-yourself.md`). Ритм брать оттуда. Правила голоса те же, что в `write-my-article`, раздел 3, они действуют целиком.

## 1. Что такое заметка

- Одна мысль. Если во входе две, написать одну, вторую предложить отдельной заметкой одной строкой в ответе.
- От одного предложения до трёх-четырёх абзацев. Больше это уже статья, сказать об этом и предложить `write-my-article`.
- Конкретика из входа: цифра, имя инструмента, случай, ссылка. Ничего не додумывать, факты только те, что дал автор. Нет факта, нет и фразы.
- Первое лицо, настоящее время, как будто сказано вслух только что. Допустимы оборванные фразы и разговорные связки автора: «если коротко», «из интересного», «кстати».
- Ссылка, если есть, вставляется inline: `[что это](url)`, без «вот ссылка» и без голого URL в тексте.
- Код и команды в бэктиках, длинное в блоке ```. Диаграммы mermaid можно, рендерятся как в статьях.

## 2. Голос, кратко

Русский, «ё», ёлочки, среднее тире «–» с пробелами, длинное «—» не использовать нигде. Читателю «ты». Ноль конструкций «не X, а Y», «не только…, но и», «это не X, это Y». Ноль канцелярита и штампов: «стоит отметить», «в контексте», «в условиях», «таким образом». Без эмодзи, без восклицательных знаков, без «давайте», без морали в конце. Оценка вместо нейтральности: автор пишет, что думает.

## 3. Файл

Имя и дата из текущего времени в UTC:

```bash
date -u +%Y-%m-%d-%H%M        # → 2026-09-25-1430, имя файла
date -u +%Y-%m-%dT%H:%M:00Z   # → 2026-09-25T14:30:00Z, поле date
```

Файл `src/content/notes/2026-09-25-1430.md`:

```markdown
---
date: 2026-09-25T14:30:00Z
---

Текст заметки.
```

- Только `date`, никаких `title` и `summary`. Заголовок ленте не нужен, в RSS первые слова текста станут заголовком сами.
- `draft: true` добавлять только если пользователь сказал «черновик». По умолчанию заметка публикуется.
- Имя файла, `date` и якорь на сайте (`/notes/#2026-09-25-1430`) должны совпадать, поэтому время берётся один раз и подставляется в оба места.
- Две заметки в одну минуту невозможны, минимум разное `ЧЧММ`.

## 4. Самопроверка

1. Одна мысль, без вступления и без вывода-морали.
2. Есть конкретика из входа, нет ничего додуманного.
3. Поискать «а не», «, а », «не только», «—»: каждую находку переписать или убрать.
4. Объём в рамках: до четырёх абзацев.
В ответ: путь к файлу, текст заметки целиком для прочтения, и одной строкой, что из входа выброшено.

## 5. Humanizer, обязательно

После черновика и самопроверки, до показа текста пользователю, вызвать скилл `humanizer-ru:humanizer-ru` через инструмент Skill (в Claude Code) в режиме локальной редактуры на созданном файле. Если инструмента Skill нет, прочитать `SKILL.md` скилла из `~/.claude/plugins/cache/ilyautov-plugins/humanizer-ru/<версия>/skills/humanizer-ru/` и пройти по его процедуре вручную. Без правил humanizer в контексте текст не отдавать.

Ограничения для humanizer в этом блоге:

- среднее тире «–» это авторский стиль, его не убирать и не заменять; строки сканера про «Короткое тире» игнорировать;
- факты, цифры, ссылки, имена и frontmatter не трогать;
- ничего не дописывать: только снимать маркеры;
- цель по сканеру: ноль маркеров кроме тире и терминов («в контексте» модели, названия дисциплин и паттернов).

Сканер: `python3 ~/.claude/plugins/cache/ilyautov-plugins/humanizer-ru/<версия>/skills/humanizer-ru/scripts/scan.py <файл>`, при необходимости через venv с `razdel` и `pymorphy3`. В ответе пользователю добавить строку «Чистота: было N, стало M» без учёта тире.

## 6. Публикация

Только по явной просьбе («запушь», «публикуй», «давай»). Тогда из корня блога:

```bash
npm run build 2>&1 | grep -E "page\(s\)|error"
git add src/content/notes/<файл>.md
git commit -m "note: <первые слова заметки>"
git push origin master
```

Сборка должна пройти без ошибок. После пуша GitHub Actions выкатывает сайт примерно за минуту, заметка появится в `/notes/`, на главной в блоке «Заметки» и в `/notes.xml`. Ссылку на заметку для телеграма дать в ответе: `https://blinov.monster/notes/#2026-09-25-1430`.

# Статья в моём стиле из транскрипции

Транскрипция – это сырьё, а не черновик. Задача: вытащить из неё одну живую мысль автора и написать статью так, будто автор сам сел и написал её за один вечер. Не пересказ речи, не конспект, не summary.

## 0. Калибровка голоса (обязательно)

Перед написанием прочитать 2–3 реальных статьи из репозитория блога (по умолчанию `/home/ubuntu/pet/my-blog/src/content/blog/`, иначе спросить путь):

- эссе/мысли: `ai/nostalgia-for-complexity.md`, `ai/how-not-to-lose-yourself.md`, `ai/world-belongs-to-generalists.md`
- техническое/инструмент: `dev/slides-in-fifteen-minutes.md`, `projects/better-ssh.md`, `projects/cronator.md`
- научпоп-лонгрид: `science/travel/duty-free-paradox.md`

Читать статьи того же типа, что пишем. Ритм и синтаксис копировать оттуда, а не из этого файла.

## 1. Разбор транскрипции

1. Выписать (для себя, не в статью) все тезисы: что автор реально утверждает, какие истории рассказывает, какие цифры, имена, инструменты, даты называет.
2. Найти **одну** центральную мысль – ту, у которой есть напряжение: неудобный вывод, парадокс, признание, «я поймал себя на том, что». Всё остальное отбросить без сожалений. Одна статья = одна мысль.
3. Сохранить сырьё, которое делает текст живым: конкретный случай, конкретный клиент/проект, конкретная цифра, конкретная ошибка автора.
4. Ничего не выдумывать. Факта нет в транскрипции – его нет в статье. Если для связки нужен факт (исследование, цифра, дата релиза) – либо проверить и дать ссылку, либо спросить пользователя, либо переформулировать без него.
5. Если тезисов на несколько разных статей – написать одну (самую сильную), а в конце ответа одной строкой перечислить, что осталось на другие.

## 2. Тип статьи и длина

| Тип | Признак | Объём | Структура |
|---|---|---|---|
| Эссе / мысль | наблюдение, позиция, рефлексия | 450–700 слов | без заголовков, без списков, только абзацы |
| Технический пост | инструмент, приём, «как я это делаю» | 300–600 слов | код-блоки, команды, минимум заголовков |
| Проект | свой репозиторий | 250–450 слов | боль → решение → как под капотом → ниша |
| Научпоп-лонгрид | внешняя тема, требует источников | 1500–3000 слов | `## Часть I…`, `**термины**` жирным, источники inline-ссылками `[текст](url)` прямо в предложении, без сносок и без списка источников в конце |

Эссе – дефолт. Лонгрид – только если пользователь явно про научпоп или транскрипция про внешнюю тему с фактами.

## 3. Голос

- Русский. Обязательно «ё», кавычки-«ёлочки». Тире – только среднее (en dash, U+2013), с пробелами по бокам. Длинное тире (em dash, U+2014) не использовать нигде, включая заголовки и подписи; дефис оставлять только внутри слов.
- «Я» – настоящее, с признанием собственных промахов: «я поймал себя», «я сам через это прошёл», «я не хочу звучать как человек, который…». Читателю – «ты», на равных, без панибратства.
- Короткие абзацы: 1–4 предложения. Одиночное предложение отдельным абзацем – как удар, ставить осознанно и нечасто.
- Конструкцию «не X, а Y» (и её варианты «Не A. B.», «вместо X – Y», «проблема не в том… а в том») **не использовать вообще**. Она узнаваема по прошлым текстам, но в новых читается как приём и накапливается быстрее, чем кажется при письме.
- Противопоставление выражать иначе: утверждением по факту («Патчить тут нечего»), уточнением через двоеточие («атаковали адаптивно: смотрели, как защита устроена»), сменой ракурса («Зацепило меня в этой работе другое»), сравнением («В авиации так же: …»), выделением слова («Ключевое слово тут – смогла»), парой определений («Промпт – это пожелание. Отсутствующий инструмент – это граница»), коротким выводом первым.
- Начало: сцена, дата, случай, эксперимент, конкретная цифра. Не «в этой статье я расскажу» (допустимо только в техническом посте) и никогда не «в современном мире».
- Конец: короткий афористичный удар в 1–2 предложения, часто переворачивающий заголовок. «Информация стала бесплатной. Умение с ней работать – никогда не было дешёвым.» Никаких «в заключение», «подводя итог», «важно отметить».
- Технические термины и названия – в оригинале: FastAPI, RLHF, chunk, retrieval, cut-off, TTFT.
- Оценка вместо нейтральности: автор пишет, что он думает, и не страхуется («это неудобный вывод», «звучит скучнее, работает честнее»).

## 4. Запрещено

- Эмодзи, восклицательные знаки, риторические вопросы пачками.
- Списки и заголовки в эссе. Если в эссе появился bullet-list – переписать прозой.
- Жирный текст как украшение (в эссе – максимум один раз, на тезисе).
- Канцелярит и AI-штампы: «стоит отметить», «играет важную роль», «в эпоху цифровизации», «не только… но и» как связка абзацев, «давайте разберёмся».
- Симметричная гладкость: одинаковая длина абзацев и предложений выдаёт машину. Ломать ритм.
- Серии однотипных конструкций: «не X, а Y» в соседних абзацах, «проблема не в том… проблема в том» дважды на текст, три абзаца подряд, начатых с одиночного предложения-удара.
- Пересказ транскрипции по порядку и фразы вроде «как я говорил выше».
- Ссылки-подпорки на несуществующие исследования. Ссылка либо реальная и проверенная, либо её нет.

## 5. Оформление файла

Frontmatter ровно такой:

```yaml
---
title: "Заголовок"
date: 2026-04-11
draft: false
---
```

- `title` – образный, короткий, часто с напряжением внутри: «Когда агент врёт тебе в лицо», «Ностальгия по сложности», «Ты уже знаешь ответ – и поэтому его получишь». Не SEO-описание.
- `date` – сегодняшняя дата, если не сказано иное. `summary` и `section` не заполнять.
- Файл: `src/content/blog/<секция>/<kebab-case-en>.md`. Секции: `ai`, `dev`, `projects`, `science` (+ подпапки), `mgmt`, `ideas`, `life`, `knowledge`. Секцию выбрать по теме и назвать в ответе.
- H1 в теле не ставить – заголовок берётся из frontmatter.

## 6. Самопроверка перед выдачей

Пройти по пунктам и молча исправить:

1. Одна мысль? Лишние тезисы вырезаны?
2. Есть хотя бы один конкретный случай/цифра из транскрипции?
3. Есть ли в тексте хоть одно предложение, которое автор не смог бы защитить в разговоре? Удалить.
4. Первый абзац цепляет без разгона? Последний – бьёт?
5. Нет ли фактов, которых не было в транскрипции и которые не проверены?
6. Абзацы разной длины, нет списков (для эссе), нет штампов из раздела 4?
7. Поискать в тексте «а не», «, а то», «Не …. …», «вместо». Каждую найденную антитезу переписать утверждением, уточнением через двоеточие, сравнением или выделением слова. Цель – ноль таких конструкций.
8. Объём в рамках таблицы. Дольше – значит, вода.

В ответ: путь к созданному файлу, тип и секция, одной строкой – что из транскрипции сознательно выброшено, и список фактов, которые стоит проверить автору.

## 7. Humanizer, обязательно

После черновика и самопроверки, до показа текста пользователю, вызвать скилл `humanizer-ru:humanizer-ru` через инструмент Skill (в Claude Code) в режиме локальной редактуры на созданном файле. Если инструмента Skill нет, прочитать `SKILL.md` скилла из `~/.claude/plugins/cache/ilyautov-plugins/humanizer-ru/<версия>/skills/humanizer-ru/` и пройти по его процедуре вручную. Без правил humanizer в контексте текст не отдавать.

Ограничения для humanizer в этом блоге:

- среднее тире «–» это авторский стиль, его не убирать и не заменять; строки сканера про «Короткое тире» игнорировать;
- факты, цифры, ссылки, имена и frontmatter не трогать;
- ничего не дописывать: только снимать маркеры;
- цель по сканеру: ноль маркеров кроме тире и терминов («в контексте» модели, названия дисциплин и паттернов).

Сканер: `python3 ~/.claude/plugins/cache/ilyautov-plugins/humanizer-ru/<версия>/skills/humanizer-ru/scripts/scan.py <файл>`, при необходимости через venv с `razdel` и `pymorphy3`. В ответе пользователю добавить строку «Чистота: было N, стало M» без учёта тире.

## 8. Публикация

Только по явной просьбе («запушь», «публикуй», «давай»). Тогда из корня блога:

```bash
npm run check 2>&1 | grep -E "errors"
npm run build 2>&1 | grep -E "page\(s\)|error"
git add src/content/blog/<секция>/<файл>.md
git commit -m "post: <заголовок статьи>"
git push origin master
```

Humanizer уже прогнан в разделе 7. Сборка без ошибок, после пуша GitHub Actions выкатывает сайт примерно за минуту. Ссылку дать в ответе: `https://blinov.monster/blog/<секция>/<файл>/`.

Короткие мысли, не тянущие на статью, идут в ленту через скилл `write-my-note`.

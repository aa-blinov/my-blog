Практикум объединяет шесть упражнений и итоговую работу на материале одного кейса. Вы опробуете каждый инструмент и увидите, как они связаны в единую рабочую среду.

## Контекст кейса

Вы руководите продуктом в SaaS-компании, которая продаёт платформу управления операциями для розничных сетей. Компания работает по облачной подписке.

*Учебный сценарий; название компании, масштаб сети и условия сделки вымышлены.* В воронке уже несколько месяцев находится ВекторМаркет, сеть из 180 магазинов. Сделка может стать одной из крупнейших в истории компании. На последнем звонке технический директор поставил жёсткое условие: данные должны храниться в закрытом контуре клиента, без размещения в облаке вашей компании.

У вас есть:

- стенограммы шести звонков с командой ВекторМаркет
- заметка менеджера по продажам о причинах трёх потерянных сделок в этом квартале
- внутренний документ с техническими ограничениями текущей архитектуры
- план продаж на следующий квартал
- данные по SLA за последние три месяца

Решение: **открывать ли отдельное направление с развёртыванием в контуре клиента и какую стратегию входа выбрать?**

## Упражнение 1. Нативный пользователь: контекстный пакет

*К лекции 1*

### Задача

Вы узнали о требовании ВекторМаркет в пятницу в 16:30. В понедельник совет директоров ждёт вашу позицию. Сначала соберите контекстный пакет, затем открывайте чат или инструмент.

### Шаги

1. Заполните шаблон из лекции 1 применительно к этой ситуации:

```text
Ситуация:

Решение:

Контекст:

Неопределённость:

Ограничения:

Хороший результат:
```

2. Разделите работу по ролям. Для каждой роли напишите, что именно вы от неё ожидаете в этом случае:

| Роль | Задача в этом кейсе |
| --- | --- |
| Разведчик | |
| Аналитик | |
| Оппонент | |
| Редактор | |
| Секретарь | |

3. Сформулируйте три вопроса, которые заставят модель проверить вашу позицию и привести серьёзные аргументы против неё.

### Ожидаемый артефакт

Заполненный контекстный пакет + таблица ролей + три вопроса для несогласия. Объём: одна страница.

## Упражнение 2. Архитектура контекста: проектное пространство для сделки

*К лекции 2*

### Задача

Сделка с ВекторМаркет будет идти ещё несколько месяцев. Нужно выстроить устойчивое проектное пространство, которое не потеряет контекст при смене участников и не превратится в папку с хаосом.

### Шаги

1. Опишите структуру проектного пространства для этой сделки. Используйте пять слоёв архитектуры контекста:

```text
Входящий сигнал:
Что попадает в пространство? Откуда?

Проектное пространство:
Как называется? Что живёт внутри?

Пакет источников:
Какие документы, стенограммы и данные относятся к этой сделке?

Память и журнал решений:
Что должно храниться как долгосрочный контекст?
Какие допущения уже приняты? Какие вопросы открыты?

Архив артефактов:
Что именно будет сохраняться как результат работы?
```

2. Составьте реестр памяти проекта по информации из описания кейса:

```text
Действующие допущения:

Ключевые решения, уже принятые:

Открытые вопросы:

Источники правды:

Дата последнего обновления:
```

3. Опишите, как подключения помогут в этой сделке: какие внешние системы или источники будет полезно подключить к пространству (CRM, база знаний команды, технический репозиторий).

### Ожидаемый артефакт

Структура проектного пространства + реестр памяти. Объём: одна страница.

## Упражнение 3. Среда принятия решений: семь проходов

*К лекции 3*

### Задача

Соберите полный контур решения о развёртывании в контуре клиента. Используйте все семь проходов из лекции 3.

### Шаги

Пройдите все семь шагов и зафиксируйте результат. Используйте предложенные запросы или адаптируйте их под ситуацию.

**Проход 1. Формулировка**

Сформулируйте точно: какое решение принимается, кто его принимает, к какому сроку и что произойдёт, если отложить.

**Проход 2. Поле вариантов**

Соберите не менее четырёх реалистичных путей. Включите как минимум один контринтуитивный.

**Проход 3. Контраргумент**

Выберите вариант, который сейчас кажется вам наиболее привлекательным. Сформулируйте самый сильный аргумент против него.

**Проход 4. Предварительный разбор провала**

Представьте: через год решение признали ошибкой. Опишите три наиболее реалистичных причины провала и ранний сигнал для каждой.

**Проход 5. Сценарии**

Опишите базовый, сильный и неприятный сценарии для предпочтительного варианта.

**Проход 6. Рекомендация**

Сформулируйте взвешенную рекомендацию. Укажите, что остаётся неясным.

**Проход 7. Упаковка**

Соберите итог в записку для принятия решения по шаблону ниже.

```text
Вопрос:

Контекст:

Варианты:

Аргументы за и против:

Риски:

Рекомендация:

Следующий шаг:
```

### Ожидаемый артефакт

Записка для принятия решения на одну страницу + список условий пересмотра.

## Упражнение 4. Маршрутизация: рабочий верстак для подготовки к встрече

*К лекции 4*

### Задача

Финальные переговоры с командой ВекторМаркет состоятся в среду. Во вторник распределите всю подготовительную работу по подходящим инструментам.

### Шаги

1. Разбейте подготовку на отдельные задачи. Для каждой заполните строку таблицы:

| Задача подготовки | Ось: глубина | Ось: источник | Ось: срочность | Ось: цена ошибки | Ось: тип выхода | Правильная среда |

| Понять, как конкуренты оформляют on-premise предложения | | | | | | |
| Поднять всё, что говорил технический директор ВекторМаркет на шести звонках | | | | | | |
| Пересчитать юнит-экономику нового направления | | | | | | |
| Подготовить краткую справку по клиенту для руководителя | | | | | | |
| Собрать вопросы, которые нужно задать на встрече | | | | | | |

2. Определите, какие задачи можно отправить в длительное исполнение на ночь, а какие требуют вашего участия утром в день встречи.

3. Опишите полный маршрут вторника: что, в какой среде, в каком порядке, с каким выходом.

Заполненная таблица маршрутизации + план дня вторника с расстановкой по средам.

## Упражнение 5. Надзор: карта надзора для контура мониторинга сделки

*К лекции 5*

### Задача

После встречи с ВекторМаркет компания решила запустить контур мониторинга: раз в неделю собирать изменения в позиции клиента по открытым каналам (пресс-релизы, вакансии, публикации), чтобы руководитель видел, не изменились ли приоритеты клиента до финального подписания.

Оформите карту надзора для этого контура.

### Шаги

1. Заполните карту надзора:

```text
Название контура:

Цель:

Разрешённые источники:

Запрещённые источники:

Разрешённые действия:

Действия только с подтверждением:

Стоп-сигналы:

Ответственный:

Частота пересмотра:
```

2. Определите точки подтверждения человеком: какие действия или выводы нельзя использовать без проверки руководителем.

3. Проверьте контур на пять типичных сбоев из лекции 5:

| Тип сбоя | Риск для этого контура | Как защититься |
| --- | --- | --- |
| Тихий дрейф | | |
| Избыточная уверенность | | |
| Перерасход полномочий | | |
| Старая память | | |
| Бесконтрольный шум | | |

4. Спроектируйте еженедельную проверку контура. Отведите на неё 5-10 минут и составьте конкретные вопросы.

### Ожидаемый артефакт

Заполненная карта надзора + таблица защиты от пяти сбоев + описание ритуала надзора.

## Упражнение 6. Нативная компания: ритм вокруг enterprise-направления

*К лекции 6*

### Задача

Компания решила открыть направление enterprise. Выстройте для него ежедневный, еженедельный и ежемесячный ритм работы.

### Шаги

1. Спроектируйте ежедневный ритм для руководителя нового направления:

```text
Утренний пакет внимания:
Что в него входит? Откуда данные? Кто готовит?

Подготовка к встречам:
Как готовится контекстный пакет? Какие артефакты нужны?

Вечерний журнал сигналов:
Что фиксируется? В каком формате? Где хранится?
```

2. Спроектируйте еженедельный ритм:

```text
Записка руководителя:
Что в ней? Кому адресована? Когда готовится?

Обзор гипотез по новому направлению:
Какие гипотезы проверяются? Кто их ведёт?

Обзор контуров:
Какие контуры нужно проверять каждую неделю?
```

3. Назначьте роли в команде для поддержки нативной работы:

| Роль | Кто подходит | Основные задачи в контексте enterprise-направления |
| --- | --- | --- |
| Хранитель контекста | | |
| Редактор артефактов | | |
| Владелец контуров | | |
| Доменный проверяющий | | |

4. Опишите первые 30 дней запуска direction: что нужно сделать, чтобы через месяц у команды уже был живой ритм, а не набор разрозненных попыток.

### Ожидаемый артефакт

Описание ежедневного и еженедельного ритма + таблица ролей + план первых 30 дней.

## Итоговый практикум. Полный интеллектуальный контур

*Объединяет все шесть лекций*

### Задача

Вы провели переговоры с ВекторМаркет. Компания решила запустить 60-дневный пилот с двумя крупными клиентами и проверить спрос на on-premise-развёртывание. В число пилотных клиентов входит ВекторМаркет.

Постройте полный интеллектуальный контур сопровождения пилота: от ежедневной работы до финального решения о масштабировании направления.

### Что нужно сделать

**Блок 1. Контекстный пакет пилота**

Оформите контекстный пакет для каждой ключевой встречи пилота: стартовой (kickoff), промежуточной (день 30) и финальной (день 60).

**Блок 2. Архитектура памяти пилота**

Спроектируйте, как будет организована память направления за 60 дней: что хранится в проекте, что в журнале решений, что в архиве артефактов. Составьте правила работы с памятью.

**Блок 3. Записка для принятия решения по итогам пилота**

Напишите шаблон записки, которую вы будете готовить на день 60. Включите: критерии успеха пилота, условия для решения «масштабировать», условия для решения «остановить», метрики и источники данных для каждого критерия.

**Блок 4. Маршрутизационная карта пилота**

Составьте карту: какие задачи в ходе пилота идут в какую среду. Укажите не менее восьми типов задач.

**Блок 5. Карта надзора для пилота**

Заполните карту надзора для основного рабочего контура пилота (например, еженедельный сбор данных по прогрессу у клиента).

**Блок 6. Ритм команды на 60 дней**

Опишите ежедневный и еженедельный ритм команды пилота. Включите роли, артефакты, точки синхронизации.

### Ожидаемый артефакт

Набор из шести артефактов, которые вместе образуют рабочую документацию пилота. Общий объём: три-пять страниц.

## Как работать с практикумом

**Минимальный формат:** пройдите каждое упражнение за 20-30 минут на реальной задаче.

**Полный формат:** пройдите весь кейс с ВекторМаркет. К итоговому практикуму у вас будут все промежуточные артефакты.

**Правило качества:** упражнение выполнено, если руководитель может использовать артефакт без дополнительных объяснений. Если его нужно пересказывать, доработайте форму.

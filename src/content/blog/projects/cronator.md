Cron молчит. Скрипт упал в три ночи с ошибкой импорта, и ты узнаёшь об этом утром, когда кто-то спросит, почему отчёт не пришёл. Или не узнаёшь вообще. [Cronator](https://github.com/aa-blinov/cronator) запускает Python-скрипты по расписанию, каждому даёт свой virtualenv через `uv`, а каждый запуск оставляет строкой в истории со stdout, stderr, кодом выхода и длительностью. Упал скрипт, приходит письмо или вебхук.

Самое интересное в его истории случилось с самим Cronator.

Первый коммит от 23 января 2026-го весит 5920 строк, и среди них синхронизация скриптов с Git. Через полтора суток её вырезали: коммит `3740bf1` стёр 603 строки. После 6 апреля репозиторий замолчал. Следующий коммит появился 6 сентября, с лицензией MIT и заменой `yourusername` на `aa-blinov` в README.

Через десять дней, 16 сентября, с 19:11 до 23:07 по UTC набежало 23 коммита. В сообщениях пункты F1-F22: заголовки безопасности, `/metrics` для Prometheus, `/health` с диском и миграциями, роли, вебхук при падении. Список выглядел как готовая система.

Три дня спустя, 19 сентября, пошёл аудит. 36 коммитов с 09:26 до 18:42, и 22 из них `fix`. В заголовках по-английски повторяется одно и то же: silently, never, forever. Скрипт, который завис без единой строки вывода, не ловил таймаут: чтение потока блокировалось раньше, чем начиналось ожидание, и запуск навсегда оставался в статусе `running`. Отмена во время установки зависимостей возвращала `False` и ничего не писала в базу, а скрипт после этого всё равно стартовал. Выключенные массово скрипты продолжали срабатывать по расписанию: в `remove_job()` передали объект вместо `script_id`.

Страннее всего вебхук из F17. Кнопка «Test Webhook» была, ручка API была, а вызова при настоящем падении не было нигде. Уведомление о сбое никого не уведомляло, пока коммит `9009a1e` не подключил его. Рядом нашёлся `min_free_space_mb`: настройка жила только полем в диагностике. Из пяти тем интерфейса работала одна, у остальных четырёх в собранном CSS не было ни одного правила. Редактор кода превратился в голый `<textarea>`: заголовки безопасности из F1 запретили CodeMirror грузиться с CDN, и браузер ничего не сказал.

Сообщения этих коммитов написаны до механизма: что зависло, где, чем проверено. Про `docker stop` там сказано, что `CMD` в shell-форме оставлял PID 1 за `sh`, SIGTERM не доходил до uvicorn, и остановка занимала все 15 секунд до SIGKILL. С `exec` те же 15 секунд превратились в 0,8, и в логе наконец появилась строка про штатное завершение.

Сейчас в `app/` 11 138 строк Python и 688 тестовых функций. Ниша прежняя: больше, чем cron, меньше, чем Airflow, один процесс без брокера и воркеров.

```bash
git clone https://github.com/aa-blinov/cronator
cd cronator
cp .env.example .env   # ADMIN_PASSWORD, SECRET_KEY, POSTGRES_PASSWORD
docker compose up -d
```

В списке фич вебхук числился готовым. Работающим он стал тремя днями позже.
